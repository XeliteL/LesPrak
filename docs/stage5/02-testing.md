# 2. Тестирование и оценка качества кода

> Черновик. Инструменты оценки качества запускались из отдельного виртуального окружения: ruff 0.17.5, radon 6.0.1, coverage 7.17.3; для Java — JaCoCo 0.8.13 (`mvn org.jacoco:jacoco-maven-plugin:0.8.13:prepare-agent test org.jacoco:jacoco-maven-plugin:0.8.13:report`) и `javac -Xlint:all`.

## 2.1. Тестовые сценарии

Тестирование выполнено на четырёх уровнях: модульные тесты процедурной реализации (23 теста, из них 4 добавлены на этом этапе), модульные тесты объектно-ориентированной реализации (27 тестов, 1 добавлен), тесты физической модели данных (19 тестов) и сквозная проверка, при которой данные проходят путь «JSON → БД → JSON → алгоритмы». Основные сценарии приведены в Таблице 2.1.

| Сценарий | Входные данные | Ожидаемый результат |
|---|---|---|
| Оценка при достаточном числе аналогов | условные данные, 300 предложений | рекомендуемая цена 20 530 000 руб. в обеих реализациях |
| Оценка без аналогов | пустой список предложений | сообщение о недостатке аналогов |
| Граница бюджета и площади | цена ровно на нижней границе бюджета, площадь ровно минимальная | объект проходит отбор |
| Пустые необязательные условия заявки | `budget_min` и `area_min` не заданы | условие не применяется |
| Сделка без даты подписания | сделка в работе, дата не назначена | сроки документов проверяются на текущую дату |
| Порог обязательного контроля | цена 5 000 000 руб. | сделка подлежит контролю по 115-ФЗ |
| Некорректные данные в БД | этаж выше этажности, ставка выше 10 %, второй договор на квартиру | СУБД отклоняет запись |
| Удаление сделки | сделка с этапами и документами | этапы и документы удаляются каскадно |
| Индексы внешних ключей | системный каталог PostgreSQL | у каждого внешнего ключа есть индекс |
| Совпадение реализаций | одни данные для Python и Java | вывод программ совпадает построчно |

Все тесты выполняются успешно.

## 2.2. Выявленные и устранённые ошибки

Ошибки, найденные при тестировании, приведены в Таблице 2.2. Для ошибок в алгоритмах и модели данных добавлены регрессионные тесты.

| Ошибка | Как обнаружена | Исправление |
|---|---|---|
| Сделка без даты подписания вызывала аварийное завершение (`KeyError` в Python, `NullPointerException` в Java) | в физической модели дата подписания необязательна; запуск на выгрузке из БД | сроки документов проверяются на текущую дату |
| Значение `null` в необязательных полях заявки вызывало `TypeError` в Python | сценарий с пустыми условиями заявки | пустое значение означает отсутствие ограничения |
| У трёх внешних ключей не было индексов, в том числе у ключа, по которому соединяет таблицы представление `property_on_sale` | запрос к системному каталогу PostgreSQL | индексы добавлены, проверка включена в тесты |
| В логической модели не было признака брака продавца | построение представления условий сделки | добавлен столбец `client.married` |
| Предупреждения компилятора о сериализации класса исключения | `javac -Xlint:all` | добавлен `serialVersionUID`, список заменён сериализуемым массивом |
| Сборщик отчёта не перенумеровывал ссылки на несколько источников, разделённых запятой | проверка собранного документа | регулярное выражение принимает запятую |

## 2.3. Оценка качества кода

Показатели качества приведены в Таблице 2.3.

| Показатель | Процедурная реализация (Python) | ООП-реализация (Java) |
|---|---|---|
| Замечания статического анализа | 3 замечания ruff, из них 2 в тестах | 0 предупреждений `javac -Xlint:all` (было 2) |
| Цикломатическая сложность | средняя 5,0; максимальная 15 (`passes_filters`) | у каждого условия заявки — отдельный метод |
| Индекс сопровождаемости (radon) | от 54 до 72 из 100, уровень A у всех модулей | — |
| Покрытие тестами | 97 % ветвей (было 94 %) | 93,3 % строк, 83,6 % ветвей |

Наибольшую сложность имеет функция `passes_filters`: в ней последовательно проверяются девять условий заявки. Её структура повторяет схему алгоритма, поэтому функция оставлена без изменений. В объектно-ориентированной реализации те же условия разнесены по константам перечисления `StandardFilter`. По результатам измерения покрытия добавлены тесты граничных значений бюджета, числа комнат и этажа, после чего модуль подбора объектов покрыт полностью.
