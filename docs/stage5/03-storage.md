# 3. Организация хранения кода, данных и документации

> Черновик.

Все материалы практики хранятся в одном репозитории системы контроля версий Git с удалённой копией на GitHub (приватный репозиторий LesPrak). Каждый этап фиксируется отдельными коммитами, поэтому любое промежуточное состояние отчёта и кода можно восстановить. Структура репозитория приведена в Таблице 3.1.

| Каталог | Содержимое |
|---|---|
| `docs/stageN/` | тексты отчёта в Markdown и собранный документ DOCX |
| `diagrams/` | исходные файлы диаграмм draw.io и их изображения PNG |
| `src/python/` | процедурная реализация, тесты, условные данные `data/sample.json` |
| `src/java/` | объектно-ориентированная реализация, проект Maven |
| `src/sql/` | физическая модель данных, загрузка данных, выгрузка и тесты БД |
| `tools/` | сборка отчёта и генерация диаграмм |

Код, данные и документация хранятся в текстовом виде, поэтому Git показывает изменения построчно. Производные файлы (DOCX, PNG, `seed.sql`) формируются скриптами из исходных, а диаграммы — генератором по описанию в коде. Физическая модель на диаграмме строится непосредственно по `schema.sql`, поэтому схема и её изображение не могут разойтись. Результаты сборки Java и кэш Python исключены из репозитория файлом `.gitignore`.

В репозитории хранятся только условные данные. При эксплуатации системы база данных будет содержать персональные данные клиентов, поэтому её резервные копии создаются командой `pg_dump -Fc realty` и хранятся отдельно от репозитория. Структура БД при этом остаётся в Git: из `schema.sql` её можно развернуть заново.
