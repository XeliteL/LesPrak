# 3. Сопоставление процедурной и объектно-ориентированной реализаций

> Черновик. Число строк посчитано без пустых строк, комментариев, строк документации и импорта.

Обе реализации дают одинаковые результаты на одних данных. Результаты сравнения приведены в Таблице 3.1.

| Критерий | Процедурная реализация (Python) | ООП-реализация (Java) |
|---|---|---|
| Представление данных | словари и списки | классы и записи с типизированными полями |
| Единица модульности | 18 функций в 5 модулях | 54 типа в 7 пакетах |
| Объём кода | около 230 строк | около 1 050 строк |
| Обнаружение ошибок | при выполнении | большей частью при компиляции |
| Добавление нового правила | изменение существующей функции | новый класс, реализующий интерфейс |
| Число тестов | 19 | 26 |

Процедурная реализация короче и почти один к одному повторяет схемы алгоритмов. ООП-реализация длиннее, но допустимые значения проверяются в одном месте, а замена правила не затрагивает остальной код. Например, новое условие заявки в Python требует изменить функцию `passes_filters`, а в Java — добавить реализацию интерфейса `RequestFilter`. Для агентства это существенно, так как правила комиссии и требования к документам меняются со временем.

Время работы на 1 000 000 записей приведено в Таблице 3.2.

| Алгоритм | Python, мс | Java, мс |
|---|---|---|
| 1. Оценка стоимости | 280,6 | 34,6 |
| 2. Подбор объектов | 434,4 | 74,2 |
| 3. Контроль документов | 843,6 | 57,6 |
| 4. Расчёт комиссии | 5 561,0 | 750,9 |

Java быстрее в 6–15 раз за счёт компиляции в машинный код, а не за счёт объектного подхода. Асимптотическая сложность в обеих реализациях одинакова. Процедурный подход удобен для отладки алгоритма, объектно-ориентированный — для системы, которую предстоит развивать.
