# 4. Состав, роли и компетенции участников команды

> Черновик. Роли и правила Scrum — по Руководству по Scrum [8], трудовые функции — по профессиональному стандарту «Программист» [9].

Требования к системе агентства меняются, а пользователи могут оценить её только в работе, поэтому разработку целесообразно вести по Scrum. Scrum-команда состоит из владельца продукта (Product Owner), Scrum-мастера (Scrum Master) и разработчиков (Developers), обычно не более 10 человек, а спринт длится не более месяца [8]. Для проекта выбраны двухнедельные спринты и команда из восьми человек (Таблица 4.1).

| Роль в Scrum | Специализация | Ответственность |
|---|---|---|
| Product Owner | представитель агентства | ведёт Product Backlog, принимает результаты спринта |
| Scrum Master | Scrum-мастер | организует события Scrum, устраняет препятствия |
| Developers | системный аналитик | требования, модели процесса и данных |
| Developers | разработчик серверной части (2) | классы, алгоритмы, программный интерфейс |
| Developers | разработчик клиентской части | веб-интерфейс агента и руководителя |
| Developers | разработчик баз данных | физическая модель данных, запросы |
| Developers | инженер по тестированию | тестовые сценарии и автотесты |

Требуемые компетенции приведены в Таблице 4.2.

| Роль | Профессиональные компетенции | Общие компетенции |
|---|---|---|
| Product Owner | рынок недвижимости, управление требованиями | переговоры, принятие решений |
| Scrum Master | Scrum, фасилитация | коммуникация, разрешение конфликтов |
| Системный аналитик | BPMN 2.0, UML, моделирование данных | аналитическое мышление |
| Разработчик серверной части | Java, ООП, шаблоны проектирования, SQL, JUnit, Git | самостоятельность, оценка трудоёмкости |
| Разработчик клиентской части | HTML, CSS, JavaScript, React | внимание к удобству пользователя |
| Разработчик баз данных | PostgreSQL, нормализация, индексы | аккуратность |
| Инженер по тестированию | тест-дизайн, автоматизация тестов | внимательность |

Профессиональный стандарт «Программист» [9] выделяет четыре обобщённые трудовые функции: A — разработка и отладка кода (уровень 3), B — проверка работоспособности и рефакторинг (уровень 4), C — интеграция модулей (уровень 5), D — разработка требований и проектирование (уровень 6). В ходе практики студент выполнял роль разработчика серверной части и задействовал функции A и B, а C и D — в объёме учебной задачи.
