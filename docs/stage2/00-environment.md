## 0.1. Состав инструментального окружения

Работа над практикой ведётся в ОС Linux (дистрибутив Arch Linux). Состав окружения определяется заданием на практику: процедурная реализация алгоритмов выполняется на языке Python, объектно-ориентированная — на языке Java, физическая модель данных строится средствами СУБД. Состав окружения приведён в Таблице 1.1.

| Инструмент | Версия | Назначение |
|---|---|---|
| Python | 3.14.7 | процедурная реализация алгоритмов (этап 3) |
| OpenJDK | 27 | объектно-ориентированная реализация на Java (этап 4) |
| PyCharm (JetBrains) | через JetBrains Toolbox | IDE для разработки на Python |
| IntelliJ IDEA (JetBrains) | через JetBrains Toolbox | IDE для разработки на Java |
| VSCodium | 1.121 | редактор для текстов отчёта (Markdown) и диаграмм |
| Draw.io Integration (расширение VSCodium) | — | построение диаграмм BPMN, UML и ER в формате `.drawio` |
| Git | 2.55.0 | система контроля версий |
| GitHub, GitHub CLI (`gh`) | — | удалённое хранение репозитория, работа с ним из терминала |

Для каждого языка используется специализированная IDE от JetBrains: PyCharm для Python и IntelliJ IDEA для Java. Обе среды устанавливаются и обновляются через единое приложение JetBrains Toolbox и имеют встроенную поддержку git. Тексты отчёта и диаграммы ведутся в VSCodium — сборке редактора Visual Studio Code из открытого исходного кода. Расширение Draw.io Integration позволяет редактировать диаграммы прямо в редакторе и хранить их в репозитории рядом с текстом. Версии установленных инструментов показаны на Рисунке 1.1, проект в IDE PyCharm — на Рисунке 1.2, редактирование диаграммы в VSCodium — на Рисунке 1.3.

## 0.2. Организация работы с системой контроля версий

Все материалы практики (репозиторий LesPrak) хранятся в одном репозитории системы контроля версий Git [1], размещённом на GitHub как приватный. Структура репозитория приведена в Таблице 1.2.

| Каталог | Содержимое |
|---|---|
| `docs/` | тексты отчёта в формате Markdown, по одному подкаталогу на этап |
| `diagrams/` | диаграммы в формате `.drawio` |
| `tools/` | вспомогательные скрипты, в том числе сборка отчёта из Markdown в DOCX |
| `src/` (с этапа 3) | исходный код: процедурная реализация на Python, ООП-реализация на Java, SQL-скрипты физической модели данных |

Текст отчёта хранится в Markdown, а не в DOCX. Так git показывает построчные изменения текста, а итоговый документ собирается скриптом с оформлением по требованиям к письменным работам.

Сообщения коммитов оформляются по спецификации Conventional Commits [2]: в начале сообщения указывается тип изменения (`docs` — документация, `feat` — новая функциональность, `fix` — исправление, `test` — тесты, `refactor` — рефакторинг). Начиная с этапа 3, работа над каждым этапом будет вестись в отдельной ветке (например, `stage-3`). По завершении этапа ветка вливается в основную ветку `main`, а итог этапа отмечается тегом. ## 0.3. Выводы

В ходе этапа подготовлено инструментальное окружение для выполнения всех этапов практики: интерпретатор Python и JDK с соответствующими IDE, средства построения диаграмм и система контроля версий. Материалы практики — тексты, диаграммы и исходный код — хранятся в одном репозитории. Выбранные соглашения о структуре каталогов, ветках и сообщениях коммитов будут использоваться на следующих этапах.
